# Design Document: Seed Service

**Component:** `src/services/seed_service.py` — Claude API company generation and CSV append.

---

## 1. Key decisions

- **Claude for generation:** Companies are generated by a single Claude API call with a prompt from config; response is parsed as JSON (with optional markdown code-fence stripping). Keeps prompt and row count in config, not code.
- **Strict field validation:** After parsing, every company dict is checked for all `config["fieldnames"]`; if any field is missing, `ValueError` is raised so bad data isn’t appended to CSV.
- **Append + dedupe:** `append_to_csv` reads existing values for `duplicate_key` (e.g. company_name), then appends only rows whose key isn’t in that set. New rows are added to the set during write so duplicates within the same batch are also skipped.
- **Overwrite vs append:** If the output CSV already exists, `_ask_overwrite_or_append()` prompts the user (overwrite = replace file, append = add rows). Overwrite deletes the file before calling Claude so the file is recreated with only the new run’s data (after generation).
- **Optional anthropic:** The module imports `anthropic` inside a try/except; if missing, `generate_companies` raises `RuntimeError` with a pip install message so the rest of the app can still run for assign/fetch.

---

## 2. Error handling — API down, missing field, write fails partway, rate limiting / retry

| Scenario | Behavior |
|----------|----------|
| **Claude API down / network error** | No try/except in `generate_companies` around `client.messages.create`. Request failures raise; `run_seed()` would crash. No retry. |
| **Claude rate limit** | No explicit handling. Rate limit response would surface as an exception and crash the seed run. |
| **Malformed JSON / wrong structure** | `json.loads(raw)` can raise `JSONDecodeError`; not caught → crash. Code-fence stripping reduces one common cause of parse errors. |
| **Missing field in generated company** | Explicit check: `if field not in c: raise ValueError(...)`. Fails fast before any CSV write. |
| **CSV write fails (disk full, permission)** | `open(...)` and `writer.writerow` would raise; not caught → crash. Partial write: if the process dies mid-loop, rows already written stay; we don’t truncate. |
| **ANTHROPIC_API_KEY missing** | Checked in `run_seed()`; raises `ValueError` with a clear message before calling Claude. |

**Summary:** No retries or rate limiting in seed. Missing-field validation prevents bad rows; API or I/O failures propagate and stop the run. CSV writes are append-only so a crash leaves previously written rows intact.

---

## 3. Idempotency — running the script twice

- **Append mode:** Second run loads existing keys from CSV, generates a new batch from Claude, and appends only companies whose key (e.g. company_name) is not already in the file. So re-running with “append” does not duplicate rows; it only adds new keys. **Idempotent in the sense of “no duplicate keys.”**
- **Overwrite mode:** User chooses to replace the file. Run 2 overwrites the file again. So “run twice” with overwrite each time gives you only the second run’s data. Not idempotent in the sense of “same state as one run” — by design.
- **Claude output non-deterministic:** Same prompt can produce different companies; so “run twice” doesn’t guarantee identical content even in append mode, but duplicate keys are still skipped.

---

## 4. What you’d improve with more time / what tripped you up

- **Retry/backoff for Claude:** Wrap `messages.create` in retries with exponential backoff for rate limits and transient errors so seed doesn’t exit on first failure.
- **Streaming or chunked generation:** For large `num_rows`, a single big response can be slow or hit token limits. Chunking (e.g. multiple smaller prompts) or streaming would help.
- **Safer CSV write:** Write to a temp file then rename to the final path so a crash doesn’t leave a half-written file; or track last written row and resume (more complex).
- **No interactive prompt in CI:** `_ask_overwrite_or_append` blocks on `input()`. For automation, support a flag (e.g. `--append` / `--overwrite`) or default to append when not a TTY.
- **Gotchas:** Prompt uses `.format(num_rows=..., fieldnames=...)`; if the prompt template contains other `{...}` (e.g. JSON examples), they can cause `KeyError`. Escaping or using a different templating approach would avoid that. Default `industry_weights` in assign assume industries like "Restaurants"/"Retail"; seed prompt should generate industries that match or configs can drift.
